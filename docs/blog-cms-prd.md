# Blog CMS 产品与实施计划（v4）

> 状态：历史需求与方案记录；自建编辑器实验已于 2026-10-22 退役。
> 当前实施设计见 [Pageel CMS Spec](specs/pageel-cms-spec.md)。部署限定为现有 Astro / Cloudflare Worker，同源接入 Pageel 工作台，复用本站 Access 与 REST，不单独部署 Node 服务。下文 v4 自建架构及勾选项不代表当前工作区能力，也不代表 Pageel 已验收。
> 需求约束继续作为迁移基线；Pageel 的认证、本地存储、MDX 兼容性缺口在新 spec 单独列明。

## 1. 产品目标与约束

在现有 `/admin/edit` 中提供可日常使用的文章管理与可视化写作体验：选择文章、编辑正文与属性、插入组件和图片、预览、保存草稿及提交发布。普通写作无需手写 Markdown 或 JSX；源码模式用于高级内容与故障恢复。

- 管理 `content/blog/` 的 `.md`、`.mdx` 和 `content/stories/` 的 `.md`。Experience、页面搭建器、多人协同和定时发布不在首版范围内。
- 管理员继续通过 Cloudflare Access 登录；本地使用现有受控开发认证。浏览器不持有 GitHub 凭证，也不出现 GitHub OAuth 或额外 CMS 登录。
- 网站继续使用 Astro 内容集合与原有文章模板。文件是持久化内容的事实来源，Git 提交提供历史记录。
- 本地经服务端写入文件；线上经 Worker 使用服务端凭证提交 GitHub。两种环境向编辑器提供同一 Interface。
- 优先采用现成 React 富文本编辑器，产品体验参考 Tina 与 Pageel；不自行实现富文本编辑内核。
- 不以“大文本框加组件插入按钮”作为可视化写作验收结果。

## 2. 当前实现与目标的差距

| 已有实现 | 判断与处理 |
| --- | --- |
| AdminApp、SessionBoundary、Access 权限与同源写入校验 | 复用；每个服务端接口仍须独立鉴权 |
| PostsEditor 的正文 textarea 和组件拼接函数 | 替换为可视化编辑工作台，保留源码编辑能力 |
| posts 的读取、保存、上传接口 | 保留入口，调整契约与内部实现，不承诺原样复用 |
| 只列出和读取 `content/blog/*.mdx` | 扩展到博客 MD/MDX 与故事 MD；已有 MD 博客不可遗漏 |
| 按行拆分 frontmatter，tags 使用 JSON.parse | 改为完整 YAML 文档解析和字段级更新；现有单引号数组、块数组、多行文本必须支持 |
| 保存时重建全部 frontmatter | 保留未编辑字段与未知字段，避免修改正文时删掉元数据 |
| 本地读取版本后直接 writeFile | 版本检查与写入需受同一文件锁保护，临时文件加原子替换；现有实现不具备完整并发保护 |
| GitHub 单文件 Contents API 和 SHA 冲突检查 | 首版可继续使用；需分别返回文件版本和提交 SHA |
| 上传后只返回公开图片路径 | 增加受保护的图片读取能力，解决部署前新图片在后台无法预览的问题 |
| 返回文章 URL 即提示提交完成 | 分开显示仓库提交状态与部署状态；草稿不能提供可访问保证 |

v3 的技术链路可作为基础，但它把当前能力写成了最终需求，缺少编辑体验、兼容性和预览的验收条件。

## 3. 选型结论

**首选验证 MDXEditor，验证通过后集成现有 React 后台。**这是待验证的技术决策，不能把库宣称支持 MDX 等同于支持本站全部 MDX。

| 方案 | 适合借鉴的部分 | 本项目的决定 |
| --- | --- | --- |
| Tina Astro Starter | 富文本、组件属性表单、页面预览与内容集合组织 | 参考交互；不直接迁移其内容查询和渲染体系 |
| AstroCMS | 从 Astro schema 生成字段、文件与 Git 管理 | 可作为独立 Node CMS 备选；需要额外运行环境 |
| Pageel CMS | React 工作台、编辑/源码/预览、服务端 Git 凭证 | 参考工作台结构；不复制整套登录和服务端 |
| MDXEditor | React 编辑内核、JSX descriptors、嵌套内容编辑、源码恢复 | 先做本站样本往返验证，再决定是否正式采用 |

Tina 的 Astro Starter 默认接入 TinaCloud；自托管还需要 GraphQL、认证、数据库与 Git provider。其富文本 MDX 模型不执行文件内 imports 和 JavaScript 表达式，直接替换会影响本站组件用法。Starter 能部署到 Cloudflare，并不等于其自托管写入后端可直接挂到现有 Worker。

MDXEditor 的 JSX descriptor 能描述组件属性与 import 来源，但不会自动执行该 import 来还原站点效果。因此“编辑组件属性”与“准确预览组件”需分别实现、分别验收。

若兼容性原型不能保留本站内容，不继续扩展自制富文本框架：重新评估独立 AstroCMS 服务，或明确内容迁移范围后再评估 Tina。不能通过默默删语法来让原型通过。

## 4. 工作台与用户流程

### 4.1 文章管理

- `/admin/edit` 默认展示文章列表：标题、集合、语言、格式、草稿状态、发布日期和更新日期。
- 支持标题/文件名搜索，集合、语言、草稿筛选。列表单篇解析失败应显示问题项，不能使整个列表不可用。
- 新建时选择博客或故事；博客选择 Markdown 或 MDX，故事固定 Markdown。
- 支持恢复当前浏览器未提交的编辑；文章路径、集合、格式和语言在创建后锁定。首版不提供改名、删除、移动和格式转换。
- 服务端返回规范文件身份与公开 URL；客户端不能自行拼接文件路径或通过文件名猜测语言。

### 4.2 写作页

- 顶部：标题、修改状态、预览入口及保存/发布动作。
- 正文：默认可视化编辑，提供源码切换；桌面可并排预览，小屏使用独立视图。
- 属性栏：摘要、语言、日期、标签、封面、分享文案、LLM 收录开关，按集合显示。
- 未保存时切换文章或离开页面需提供恢复保障；切换视图不产生仓库写入。
- 支持中文输入法、撤销/重做、粘贴、长文滚动；避免每次输入重建编辑器。
- 仅有 `admin:read` 的会话可以查看文章；编辑、草稿恢复应用、上传和保存要求 `admin:write`。

### 4.3 三种内容状态与动作

| 状态/动作 | 语义 |
| --- | --- |
| 浏览器暂存 | 输入停止后暂存正文、属性、文件身份和基准版本；不产生 Git 提交，只保障本浏览器恢复 |
| 保存草稿 | 新文章或仓库草稿明确保存 `draft: true`；本地写盘，线上提交仓库 |
| 发布文章 / 更新已发布文章 | 明确保存 `draft: false`；线上结果首先是“已提交，等待部署” |

已经发布的文章在编辑中使用浏览器暂存；不提供会把原文改为 `draft: true` 的“保存草稿”按钮，避免意外下线。服务器上的已发布文章修订草稿是后续能力，需要另设工作分支或草稿存储。

暂存记录按仓库、集合和文件身份区分，保留基准版本与时间。恢复时若仓库版本变化，进入差异处理；不自动覆盖。浏览器暂存不等于跨设备备份，界面应清楚显示“本机暂存”。

## 5. 内容模型与兼容规则

### 5.1 文件与 URL

| 集合 | 文件 | 公开 URL 规则 |
| --- | --- | --- |
| Blog | 保留现有 `content/blog/**/*.md` 与 `**/*.mdx` 路径 | 英文 `/blog/{id}`；中文 `/zh/blog/{id去掉末尾-zh}` |
| Stories | 保留现有 `content/stories/**/*.md` 路径 | 英文 `/stories/{id}`；中文 `/zh/stories/{id}`，不套用博客的后缀移除逻辑 |

- `lang` 来自 frontmatter，缺省按现有 schema 为 `en`。如 `ai-draft-generation-queue-sse-guide.mdx` 是中文，不能按文件名判断为英文。
- 新博客：英文 `{slug}.{md|mdx}`，中文 `{slug}-zh.{md|mdx}`；沿用现有 slug 约束。
- 新故事：使用用户选定的 `{slug}.md`，语言仅由 frontmatter 决定，不自动加 `-zh`。
- 同一 URL 不允许被两个文件占用，必须检查 `.md`/`.mdx` 及中文后缀归一化后的冲突。
- 已有不符合新建命名约定的文件可以原位编辑；新建约束不能反过来阻止读取旧内容。
- 路径仅允许目标集合内的受支持文件，规范化后检查路径穿越；本地还需拒绝通过符号链接越界。

### 5.2 Frontmatter

以 `src/content.config.ts` 的集合 schema 为内容约束来源。实施时抽取可被 Astro 与服务端共同使用的 schema，保持所有现有内容兼容，不另造一份会逐渐偏离的校验规则。

- 使用 YAML 文档解析器更新被编辑字段；未编辑字段、未知字段和可保留的注释不得丢失。
- 标题、摘要、发布日期为保存到仓库的必填项；浏览器暂存允许未完成字段。
- 日期兼容已有可解析格式，不将原有时间戳无意截为日期。新文章默认日期表单。
- 标签支持已有中文标签；英文标签统一小写，不使用仅接受英文 slug 的正则限制全部标签。
- 现有封面路径与合法外部图片地址应保留，不能因上传目录约束而拒绝保存旧文章。
- 无操作打开/关闭不产生修改或提交；只改属性时正文原始字节保持不变。

### 5.3 编辑能力

| 内容 | 首版目标 |
| --- | --- |
| 博客 Markdown | 标题、段落、列表、引用、链接、图片、表格、代码块的可视化编辑 |
| 常用 MDX 组件 | 首批 ExploreCard、BlockQuote、PreviewLink：插入、属性编辑、嵌套正文编辑 |
| 公式 | 保留 `$...$`、`$$...$$`；提供公式源码输入与 KaTeX 预览，编辑器插件需要原型验证 |
| 复杂 JSX、对象表达式、未知组件 | 完整保留；无法可靠转换时整篇进入源码模式，并说明具体不支持的节点 |
| Stories | 纯 Markdown；仅提供文本、强调、链接、段落、分隔线与换行能力，不提供图片、标题、代码、公式或组件插入 |

建立显式组件注册表，记录组件名、默认/命名 import、路径、属性、嵌套内容、hydration 指令和预览实现。保留已有 `client:load`、`client:visible`、别名与命名导入。新插入组件按仓库约定生成指令，重型可视化不得默认 `client:load`。

转换必须按语法树处理；不能用字符串替换删除 import、改写属性或拼接组件。未知语法不得静默丢弃。可视化编辑允许格式化已编辑正文，但语义必须保持，且保存前可查看差异。原始正文始终保留用于恢复。

新建 MDX 博客提供 Snippet of the Week 模板；引用型文章支持 References 结尾。纯 MD 新文需要 ExploreCard 时提示创建为 MDX，不静默转换文件扩展名。故事遵守仓库的纯文本与段落风格要求；已有内容的标点等风格问题只提示，不自动改写。

## 6. 预览设计

**首版提供未保存内容的排版预览，不承诺任意 MDX 的 Astro 构建效果实时重现。**

- 可视化编辑和预览共用当前内存文档，不以已部署页面代替未保存内容。
- Markdown 预览复用站点排版样式，并对齐代码高亮、表格、目录和数学公式配置；博客与故事分别验收。
- 通过 AST 和显式注册表渲染受支持 MDX 组件；编辑器预览不执行文章中的任意 imports 或 JavaScript 表达式。
- 未支持的交互组件显示带名称和说明的占位，不显示空白，不声称与线上一致。
- 原型必须验证组件的嵌套正文、静态属性与 `client:*` 保留；重型组件在编辑区使用轻量表示。
- 图片上传成功后用受鉴权的媒体读取地址展示；写入正文的仍是最终公开路径。部署后正常使用公开路径。
- 本地保存后可用 Astro 页面验证真实渲染；未发布草稿不应被导向会返回 404 的公开页面。
- 线上真实效果以该提交的成功构建和部署为准。需要任意 MDX 的发布前完整预览时，后续新增独立分支构建/预览部署，不在 Worker 请求中运行整个 Astro 构建。

## 7. 模块设计

采用四个 Module，避免把文档解析、存储和 UI 状态混在 PostsEditor 或一个 service 文件里。

| Module | Interface 对调用方承担的职责 |
| --- | --- |
| 编辑工作台 | 管理选择、属性、正文、暂存、差异与保存状态；不接触 GitHub 凭证和文件系统 |
| 文档处理 | 解析/校验 frontmatter 和正文、保留旧内容、生成规范文件身份和 URL、判断可视化能力 |
| 内容存储 | 列出、读取、带预期版本写入；隐藏本地文件与 GitHub 差异，并返回新的文件版本和可选提交 SHA |
| 媒体处理 | 验证图片、保存、生成持久引用与后台预览地址 |

本地文件 Adapter 与 GitHub Adapter 是真实的两种实现，放在内容存储的 Seam。首版不为尚不存在的 CMS、数据库或存储供应商增加通用插件框架。

共享请求/响应类型放在 `src/shared/admin/`；客户端不再从 `src/server/` 导入业务契约。编辑器内核仅在后台浏览器中加载，避免进入前台文章 bundle 或执行 SSR。

## 8. 接口与保存契约

继续使用 `/api/v1/admin/posts`，将其定义为博客与故事的统一内容入口。

| 方法 | 路径 | 目标能力 |
| --- | --- | --- |
| GET | `/api/v1/admin/posts?collection=…` | 返回文章元数据、格式、文件身份、版本及错误项 |
| GET | `/api/v1/admin/posts/read?collection=…&filePath=…` | 返回属性、原始正文、文件版本、规范 URL 与兼容性说明 |
| POST | `/api/v1/admin/posts/save` | 校验集合/格式/身份、预期版本和字段变更，保存文档 |
| POST | `/api/v1/admin/posts/upload` | 博客图片上传，返回公开路径与后台预览地址 |
| GET | `/api/v1/admin/posts/media?path=…` | 受保护地读取允许目录的图片；不可作为任意 URL 代理 |
| GET | `/api/v1/admin/posts/deployment?commitSha=…` | 查询对应提交的工作流状态；无法确定时返回 unknown |

- 所有读取要求 `admin:read`；写入要求 `authorizeAdminMutation(..., 'admin:write')`，校验来源并限制请求体大小。
- 更新以服务器验证的 `collection + filePath` 为身份，不能利用提交的 slug 改写其他文件。新建由服务器生成路径。
- 新建 `expectedVersion: null`；编辑提交读取时的版本。不匹配返回 409，同时保留本机编辑，允许重载比较或导出。
- 版本是 opaque string：本地可用内容哈希，GitHub 为文件 blob SHA；不要把它当成 commit SHA。
- 保存返回 `filePath`、`version`、`commitSha?`、`publicUrl`、`draft` 和 `persistence: local | git`。暂存和已保存状态分别显示。
- 请求超时后先重新读取并比较目标内容，确认是否已写入，再允许重试；不能在未知结果下重复提交或覆盖新版本。
- 服务端进行 schema 与语法检查；语法通过不保证组件 import 可解析，完整编译仍由构建完成。
- 文档大小暂定上限 900,000 字节，这是本产品首版保护限制，不是 GitHub 的通用文件大小上限。
- 列表读取限制并发；避免每次按键扫描 GitHub。只为列表缓存元数据，保存前必须读取/检查当前版本。

## 9. 图片与发布链路

图片写入 `public/images/blog/{lang}/{slug}/`，接受文件头和大小校验通过的 PNG、JPEG、WebP，单张最多 4 MiB。支持文件选择、拖拽、粘贴和 alt 文本；上传中、失败、重试状态必须可见。正文尚无 slug 时先完成文件身份设置。

首版允许图片与文章分别提交，接受额外构建和未引用图片这一取舍。放弃文章不自动删除已上传文件；后续清理必须检查引用。第三方图片继续遵守 imageCredits 规则：首版 CMS 上传限定原创素材，第三方新增素材通过仓库补齐署名后再引用。

线上由 Worker Secret 中的 GitHub 凭证提交到 main，仓库与分支仅由服务端配置决定。凭证需要目标仓库 Contents 写权限；查询工作流状态还需要相应读取权限。使用可触发 push 工作流的独立凭证；GitHub Actions 自带 GITHUB_TOKEN 的提交不能被当成自动触发后续工作流的保证。

发布状态依次区分：提交中、已提交/等待构建、构建或部署中、部署成功、失败、取消、未知。必须关联 commit SHA；不能把最近一次工作流成功当成本次文章已上线。现有 workflow 会取消旧任务，取消或被后续提交覆盖时不可显示成功；若没有可靠证据则显示待确认及工作流链接。

首版继续直接提交 main：保存接口成功仅表示文件进入仓库。构建失败不会使这次内容上线，但会留下需要修复的仓库版本。界面提供构建记录和继续修复入口，不能展示“已发布成功”。若需要在进入 main 前保证构建通过，后续采用分支/PR 发布流程。

本地仅显示“已写入本地文件”，不显示 GitHub 已提交或线上已发布。

## 10. 实施顺序与交付门槛

### 阶段 A：兼容性原型（选型门槛）

在不覆盖原文的测试副本上接入 MDXEditor，验证：

- `astro-to-nuxt-ecosystem-fullstack.md`：Markdown 图片、列表、表格和代码。
- `ai-draft-generation-queue-sse-guide.mdx`：长文、中文语言识别、ExploreCard 与嵌套内容。
- `miles.mdx` / `miles-zh.mdx`：命名 imports、内联嵌套 JSX、对象属性、client 指令；不支持部分必须明确回退源码并保持原文。
- `fragments.md` / `fragment.md`：YAML 单引号标签、中文标签、换行、分隔线与强调。
- 补充最小样本覆盖 KaTeX、多行 YAML、未知字段、未知组件和不合法 MDX。

验收：打开→切换视图→编辑普通段落→保存→重开，未编辑组件与元数据不丢失；普通 Markdown、ExploreCard 及其嵌套内容必须能可视化编辑。复杂文章的回退范围需记录，不能以全部回退源码作为通过。

### 阶段 B：内容与存储修正

完成完整 YAML、共享 schema、MD/MDX/Stories 支持、文件身份和 URL 校验、并发保护、共享契约。通过现有内容读取与针对性冲突测试。

### 阶段 C：工作台与预览

### 阶段 D：发布验收

完成 commit SHA 与部署状态关联；在明确授权的测试发布中验证 GitHub 提交、工作流触发、部署完成及公开页面。没有完成真实生产验证时必须标为未验收。
