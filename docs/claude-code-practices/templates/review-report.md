# 审查报告模板

按实际复杂度裁剪，但必须保留范围、发现、验证和未验证项。无需粘贴全量终端输出或为不适用能力填写大量空表。

## 范围

- 模式：branch / worktree / snapshot。
- 基点与 HEAD：解析后的 SHA；snapshot 标记不适用。
- 路径：审查对象及追踪到的依赖。
- 是否包含未提交、未跟踪内容；用户明确排除的范围。

## 发现

按 Critical → High → Medium → Low 排序。同一根因合并，明确“本次变更引入”或“当前实现已有”；推测与可选设计建议另列。

### [严重度] 具体问题

- **位置**：当前文件及准确行号；删除的代码注明基点版本。
- **触发与影响**：什么输入/状态会触发，调用方会观察到什么结果。
- **证据**：实际复现、测试输出，或能够完整推导的调用链；引用规则不能替代行为证据。
- **建议**：最小且可验证的修复方向，以及需要覆盖的回归场景。

没有可确认的问题时明确说明。纯命名偏好、未接入能力或未经验证的假设不作为已确认缺陷。

## 验证

| 命令或方法 | 结果 | 证据与边界 |
| --- | --- | --- |
| 实际执行的命令 | 通过 / 失败 / 未执行 / 不适用 | 关键输出、环境和实际覆盖范围 |

按需附上关键调用链或扫描判断。说明已有警告、工具缺失、内存耗尽等限制，不能用退出码或其他检查成功掩盖它们。

## 未验证项与建议

- 未验证的行为、原因、风险及后续补验方式。
- 与已确认缺陷分开的架构建议，说明收益及适用时机。
- branch/worktree：合并建议及阻塞项。
- snapshot：当前完成度及优先补齐事项；不要套用 PR 合并结论。

无需自动保存报告或追加历史日志。用户要求产物文件时再写入指定位置。
